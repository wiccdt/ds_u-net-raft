# Video Object Segmentation with U-Net + Optical Flow

Исследовательский проект по видеосегментации объектов на датасете **YouTube-VOS**. Реализованы и сравнены два подхода: базовое дообучение U-Net с передачей предыдущей маски и дообучение с интеграцией оптического потока (RAFT).

---

## Задача

Бинарная сегментация объектов в видеопоследовательностях. На вход модели подаётся текущий кадр и предсказанная маска предыдущего кадра, на выходе — маска объекта в текущем кадре.

---

## Архитектура

- **Backbone:** U-Net с энкодером ResNet-34, предобученным на ImageNet (`segmentation_models_pytorch`)
- **Вход:** 4-канальный тензор — RGB кадр + маска предыдущего кадра
- **Выход:** бинарная маска (sigmoid)
- **Стратегия обучения:** заморозка энкодера, дообучение только декодера (12.9% параметров — 3.15M из 24.4M)
- **Функция потерь:** комбинированная BCE + Dice loss с `POS_WEIGHT=6.65` для компенсации дисбаланса классов (объект занимает ~13% пикселей)

### Модель 2 — с оптическим потоком

Предыдущая маска трансформируется с помощью векторного поля оптического потока, вычисленного моделью **RAFT** (`raft_small`). Это позволяет передавать модели приближённое положение объекта в текущем кадре с учётом его движения.

---

## Датасет

**YouTube-VOS** — видеопоследовательности с попиксельной разметкой объектов.

- Обучение / валидация: 4000 / 200 кадров (выборка из датасета)
- Формат аннотаций: PNG-маски, `meta.json` с описанием видео и объектов
- Аугментация `prev_mask`: случайное эрозирование, дилатация, сдвиг (±15px)f

---

## Результаты

### Базовая модель (без оптического потока)

| Режим | IoU | Dice | Pixel Accuracy |
|---|---|---|---|
| Zero-shot | 0.1152 | 0.1990 | 0.1156 |
| После дообучения | **0.2221** | **0.3134** | **0.8685** |


- Early stopping на эпохе 20, лучшие веса — эпоха 17
- Доля предсказанных объектных пикселей: с 99.95% (zero-shot) до 11.26% (≈ реальная доля 11.51%)
- Доля почти пустых масок: 7.5% кадров (объект не обнаружен)

### Модель с оптическим потоком (RAFT)

| Режим | IoU | Dice | Pixel Accuracy |
|---|---|---|---|
| Zero-shot (flow) | 0.1171 | 0.2019 | 0.1336 |
| После дообучения | 0.2066 | **0.3204** | 0.5862 |

- Early stopping на эпохе 13
- Доля предсказанных объектных пикселей: 47.49% — систематическая переоценка из-за артефактов warp
- Доля почти пустых масок: 0% (flow-маска «навязывает» наличие объекта)

### Покадровое сравнение (200 кадров)

| | Кадры |
|---|---|
| Flow лучше базовой (IoU diff > 0.02) | **99** |
| Flow хуже базовой (IoU diff < −0.02) | 85 |
| Примерно одинаково | 16 |

## Параметры обучения

| Параметр | Значение |
|---|---|
| Batch size | 16 |
| Epochs (макс.) | 25 |
| Learning rate (декодер) | 1e-4 |
| Optimizer | Adam |
| Scheduler | ReduceLROnPlateau (factor=0.5, patience=2) |
| Early stopping patience | 5 |
| Input size | 256×256 |

## Выводы

Оба подхода показывают практически идентичное качество на тестовой выборке: IoU 0.2221 против 0.2066, Dice 0.3134 против 0.3204 — разница находится в пределах статистической погрешности на 200 кадрах. Добавление оптического потока через RAFT не даёт значимого прироста качества при такой постановке эксперимента.
Покадровый анализ показывает, что flow и базовая модель просто побеждают на разных кадрах (99 vs 85), не давая никому устойчивого преимущества. Оптический поток полезен при плавном движении, но вносит шум при окклюзиях и быстрых сменах — эти эффекты компенсируют друг друга в итоговой метрике.
